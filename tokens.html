Tokens and embeddings

A model can only compute with numbers. Follow one sentence as it turns into tokens, then IDs, then rows of learned numbers.

Text → tokens → IDs → embeddings

Follow a sentence into the model

Type a sentence. The tokenizer cuts it into tokens and looks up each token's ID in its vocabulary. The model then uses each ID to fetch one row from its embedding table.

Vocabulary: every token the tokenizer knows, with its ID

Where the rows come from

Embeddings are learned, not written

Every row starts as random numbers. Training uses the same task as the Tiny LLM Lab, predicting the next token, and nudges these numbers each time. Each row has 2 numbers here, so every token can be drawn as a point on a map. Real models use thousands of numbers per row.

What about new words?

Why real models use pieces of words

A word tokenizer only knows whole words from its training text. Real LLMs learn subword pieces instead (byte-pair encoding, BPE): start from single letters, then repeatedly glue together the pair that appears most often in the training text. Any new word can be built from pieces.
