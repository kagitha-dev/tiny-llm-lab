Tokens and embeddings

Before a model can compute anything, text has to become numbers. A tokenizer cuts the text into tokens and gives each one an ID. The model then uses each ID to fetch a row of learned numbers from its embedding table.

text→tokenizer→token IDs→embedding table→layers→scores→next token
Step 1 · Tokenize

Text becomes tokens and IDs

Word tokenizer

One token per word, the way the Tiny LLM Lab works. A word it never saw becomes [UNK] (unknown), so its meaning is lost.

Subword tokenizer (BPE)

How real LLMs tokenize. It starts from single characters and learns to merge the most frequent neighbours into bigger pieces. Any word can be built from pieces, so nothing is unknown. ▁ marks the start of a word.

Step 2 · Embed

Each ID fetches a row from the embedding table

The embedding table is part of the model's weights: one row of numbers per token. Here each row has 2 numbers so it can be drawn on a flat map. Real models use hundreds to thousands of numbers per row. The tokenizer has no weights; it only decides which rows to fetch.

Step 3 · Learn

Embeddings start random and are learned

The embedding rows are trained the same way as the weights in the Tiny LLM Lab: guess the next token, measure the error, nudge the numbers. Here the guess goes through the embedding first, so the training also moves each token's point on the map.

In a real LLM, the fetched rows then pass through many layers where every token's numbers are mixed with the others before the next-token scores come out. Back to the Tiny LLM Lab.
